<objective>
Build this phase's real access-control surface: a server-side, unbypassable approval gate and per-scene retry caps that sit inside the single function that dispatches a paid Veo call, and make that function resolve its own image path from the database instead of trusting the browser.

Purpose: APPROVAL-01's wording is "through any path, not just the visible UI" — a disabled React button is not the requirement. D-01 and D-02 make approval a real, persisted, once-per-story decision; D-03 makes each scene's retries a bounded, env-configurable number so an accidental click-loop cannot burn real money on one stuck scene. Everything the rest of Phase 4 builds (the Approve control, the batch dispatcher, the retry button) calls through this gate, so it has to exist and be proven first.

Output: One Prisma migration adding Story.imagesApprovedAt, Scene.imageAttempts, Scene.videoAttempts and a GENERATING value on SceneAssetStatus; a pure, zero-I/O gate module; an env-configurable retry-cap reader; a refactored generateSceneVideoAction(storyId, sceneNumber); a shared temp-database test helper; and a new structural boundary invariant that keeps the paid dispatch points single.
</objective>

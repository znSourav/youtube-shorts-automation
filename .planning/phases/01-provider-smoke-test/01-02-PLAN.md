<objective>
Build the two pure-logic utilities every paid call in this phase depends on: the $3.00 spend-ceiling
ledger (D-04, D-05) and a response logger that can dump a raw provider response without emitting a
megabyte of base64 or a secret.

Purpose: these are the only failure paths in the phase that can be proven without spending money. You
cannot test "refuses the call at $2.80 spent" by making a real call — you have to test it here, before
any key is even required. RESEARCH.md's `## Don't Hand-Roll` key insight names the ledger as the one
genuinely custom piece of plumbing this phase writes; the redacting logger is the enabling half of
Pitfall 1's mandatory "log the raw response before writing any parsing code" instruction.

Output: `src/lib/spend-ledger.ts` and `src/lib/log-response.ts`, each with a `node --test` suite.

This plan makes no network calls and needs no API key. It is safe to run before the key exists.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-process values -> stdout / log files / SUMMARY.md | Anything printed here is durable and may be pasted into an issue. The API key must never cross. |
| `storage/_smoketest/spend-ledger.json` -> paid-call authorization | This file is the only thing standing between a retry bug and real money. Its read path is a security-relevant control, not bookkeeping. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `logRawResponse` / `redactLargeStrings` in `src/lib/log-response.ts` | high | mitigate | Any value under a key whose lowercased name contains `key`, `token`, or `authorization` is replaced wholesale — never truncated, since a prefix of an API key is still a disclosure. Unit-tested with a key-shaped fixture asserting the value is absent from the serialized output. |
| T-01-02 | Denial of Service (against the $15 budget) | `checkCeiling` in `src/lib/spend-ledger.ts` | high | mitigate | Hard $3.00 gate (D-05) that throws rather than returning an ignorable boolean, refusing any call whose projected total would exceed it. Non-finite and negative estimates throw rather than pass, so a broken cost calculation cannot disarm the gate. Refusal and boundary paths are unit-tested — they cannot be exercised by real calls without spending the money the gate exists to protect. |

A single local operator could still hand-edit the file; that residual risk is accepted for throwaway scaffolding that Phase 5's BUDGET-01..05 system replaces. |

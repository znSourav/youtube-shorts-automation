## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action | `storyId` arrives as an untrusted, client-supplied serialized argument on the folder-open and finalize paths; the list action deliberately takes no argument at all |
| Server Action → operating system | the highest-consequence boundary this product has: a string becoming an argument to a spawned process |
| Server Action → local filesystem (write) | the export creates, overwrites, and removes files under a directory named by that same client-supplied id |
| Server Action → browser | every returned field is a candidate for leaking a filesystem path or provider text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07 | Tampering (command injection) | `openStoryFolderAction` → `execFile("explorer.exe", [...])` | high | mitigate | `storyDir(storyId)` runs first and throws on any id outside `^[a-z0-9-]+$`, so no separator, dot-segment, quote, or shell metacharacter can survive into the argument; `execFile` passes an argument array with no shell, so no quoting or parsing layer exists to exploit even if validation were bypassed; `check-boundaries.ts` invariant 6 (Task 2) makes a second process-spawning call site anywhere in `src/` a failing structural gate rather than a review miss (04-RESEARCH.md Security Domain) |
| T-04-08 | Tampering (path traversal on write) | `exportEpisodeAssets`'s `copyFileSync`, `writeFileSync`, and `rmSync` targets | high | mitigate | Every destination is produced by a `storage-paths.ts` builder that routes through `assertValidStoryId`/`assertValidSceneNumber` and throws rather than concatenating; every source is the database's own recorded path for a scene of that same story, never a client string; the export propagates the id-validation throw instead of swallowing it, so a bad id produces no write at all — asserted directly by a test |
| T-04-03 | Information Disclosure | `EpisodeOutputResult` and `ListStoriesResult` crossing back to the browser | medium | mitigate | `EpisodeOutputResult` declares a boolean, a sentence, and a count; `LibraryStoryRow` declares an id, a title, an ISO date, a label, and a count; neither type has a path-shaped field for a path to land in, and a test asserts no `LibraryStoryRow` key matches `/path/i` — the same structural guarantee `story-view.ts` already documents (T-03-15) |

<objective>
Close RELIABILITY-01: every provider failure is caught, classified by its real cause, and surfaced as a calm plain-language sentence chosen by that cause — a content block says rephrase, a technical failure says try again — while no single hung HTTP request can ever starve the app's shared dispatch queue again.

Purpose: `gemini-image.ts` already proves the exact classification shape D-01 asks for. This plan extends that one proven pattern to the two providers that lack it (video has no discriminator at all; the story path collapses three distinct causes into one message) and closes the confirmed unbounded-hang gap at its root, in the SDK's own supported mechanism.

Output: a shared timeout configuration module, a `blockKind` discriminator on the video provider with its first unit test, a `blockStage`-aware story failure message, and two new build-time invariants that keep both guarantees from silently regressing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider response → Server Action return value | Where raw `blockReason` / RAI reason strings could leak into a wife-facing message |
| Provider HTTP request → shared `serializeDispatch` queue | Where one unbounded request starves every future paid dispatch |
| Failure classification → retry-cap bookkeeping | Where a new branch could accidentally make the cap conditional on cause |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05 | Denial of Service | `serializeDispatch` (`src/core/budget/dispatch-chain.ts`) wedged by a hung provider HTTP call | high | mitigate | A timeout option is added to all six Google GenAI call sites from `src/core/config/provider-timeouts.ts`; check-boundaries invariant 8 fails the build if a provider file that imports the SDK loses either the timeouts import or the config key. |
| T-06-06 | Information Disclosure | Raw `blockReason`, RAI reason strings, or `detail` reaching the browser through the new differentiated branches | high | mitigate | Every new branch returns one of five named exported constants; `blockReason` and `detail` are never interpolated into a returned message. Tests assert each constant excludes provider, model, and reason-code substrings. |
| T-06-07 | Tampering | The retry-cap increment becoming conditional on failure cause, letting a repeatable failure loop past its cap (D-02) | medium | mitigate | check-boundaries invariant 9 asserts the awaited `incrementVideoAttempt` call appears exactly once in `generate-video.ts` and textually precedes the awaited `generateVideo` dispatch, on comment-stripped source. |
| T-06-08 | Denial of Service | A timeout set too tight aborting a legitimately slow but successful paid call, wasting real money | medium | accept | Values are set deliberately generously (3 min LLM, 2 min image, 1 min per video request) against a defense-against-infinite-hang goal, per 06-RESEARCH.md Assumption A3; they are named tunable constants in one module, and a retry after an abort still passes the unchanged budget gate. |
